# 免费部署到公网指南

> 目标：拿到一个公开网址，别人（含手机）打开就能用，**全程不花钱、不买服务器**。
> 我准备了两种方案，文件夹里两套代码都已完成并通过测试。

---

## 一、两种方案怎么选

| | 方案 A：纯静态版（推荐先用） | 方案 B：Node 服务端版 |
|---|---|---|
| 代码位置 | `公网版聊天室\` | `网页版聊天室\` |
| 需要服务器吗 | **完全不需要** | 不需要买，用免费云平台 |
| 实时通信 | 走免费公共 MQTT 服务 | 自己的服务端（SSE） |
| 部署难度 | 拖拽上传，1 分钟 | 需注册 GitHub + Render，约 10 分钟 |
| 功能 | 公聊、私聊、在线列表、公告、禁言、踢人 | 同左 + **历史消息**、真正的权限管控 |
| 弱点 | 无历史消息；管理权限靠前端自觉（防君子不防小人）；消息经公共服务中转 | 免费实例 15 分钟无访问会休眠，首次打开要等约 50 秒 |
| 适合 | 同学/朋友之间玩、演示、作业 | 想长期稳定用、需要历史记录 |

> 建议：先用方案 A 快速上线（真的 1 分钟），觉得不够再升级方案 B。

## 二、方案 A：纯静态版上线（最简单）

### 需要上传的文件（3 个）
```
公网版聊天室\index.html
公网版聊天室\mqtt.min.js      ← 已下载到本地，不依赖任何 CDN
```

### 方式 1：Cloudflare Pages（国内访问相对最好，推荐）

1. 打开 https://dash.cloudflare.com/sign-up ，用邮箱注册（免费，不用绑卡）
2. 登录后左侧找到 **Workers 和 Pages** → **创建** → **Pages** → **上传资产**
3. 项目名称随便填，例如 `mychat` → 把上面 2 个文件拖进去 → **部署站点**
4. 完成后得到网址：`https://mychat.pages.dev` ← 这就是公网地址，发给谁都能打开
5. 以后改代码：进入项目 → **创建新部署** → 重新拖文件即可

### 方式 2：GitHub Pages

1. 注册 https://github.com → 右上角 **+** → **New repository**
2. 仓库名如 `mychat`，选 **Public**（必须公开）→ Create
3. 点 **Add file → Upload files**，上传 `index.html` 和 `mqtt.min.js` → Commit
4. 仓库页 **Settings → Pages** → Source 选 **Deploy from a branch**
   → Branch 选 `main`，目录选 `/ (root)` → Save
5. 等 1~2 分钟，访问 `https://你的用户名.github.io/mychat/`

### 方式 3：Netlify Drop
1. 打开 https://app.netlify.com/drop
2. 直接把 `公网版聊天室` 文件夹拖进页面 → 得到 `https://xxx.netlify.app`
3. 按提示注册账号即可长期保留这个网址

### 上线后怎么用
- 所有人都打开同一个网址，**房间号填一样的**（默认 8888）就能互相看到
- 想换房间就改房间号，不同房间互不干扰
- 管理员：密码 `123456`（在 index.html 开头 `ADMIN_PWD` 可改）
- 手机也能用，页面已适配窄屏

## 三、方案 B：Node 服务端版上线（Render 免费）

### 准备
1. 注册 https://github.com
2. 新建仓库（Public），上传 `网页版聊天室\server.js` 和 `网页版聊天室\index.html`
3. 注册 https://render.com ，选 **GitHub 登录**（免信用卡）

### 部署
4. Render 控制台 → **New +** → **Web Service** → 选刚建的仓库
5. 按下表填写：

| 选项 | 值 |
|---|---|
| Language / Runtime | Node |
| Build Command | （留空，没有依赖要装） |
| Start Command | `node server.js` |
| Instance Type | **Free** |

6. 点 **Create Web Service**，等 1~2 分钟构建完成
7. 得到网址 `https://xxx.onrender.com`，直接可用

### 保活（很重要）
免费实例 15 分钟没人访问就会休眠，再次打开要等约 50 秒。
- 注册 https://cron-job.org （免费），新建一个每 10 分钟访问一次你网址的任务，即可基本保持常醒。

### 其他免费平台
- **Railway**：需绑卡（有额度），稳定性好
- **Fly.io**：需绑卡
- **Vercel**：❌ 不适合，Serverless 函数不支持这种长连接推送

## 四、关于“别人搜索网址就能打开”

- **把链接发给别人，立即就能打开**，这一点没问题。
- 被搜索引擎收录需要时间（几天到几周），且不是必然。页面里已经写了标题和简介（`<title>`、`description`），有助于收录。
- 想尽快被搜到：把网址发到公开的地方（如自己的主页、博客），搜索引擎更容易发现。
- 国内环境下，`*.pages.dev`、`*.netlify.app`、`*.github.io` 一般都能访问但速度一般；想要国内高速稳定访问需要买国内云服务器 + 域名备案，那就不免费了。

## 五、安全与使用提醒

- 静态版的消息经过**免费的公共 MQTT 服务器**（EMQX / HiveMQ 的公共测试服务）中转：
  - 消息**不加密存储、没有历史记录**
  - 任何人都可能连接同一主题，**不要发密码、身份证号等敏感信息**
  - 公共服务器有速率限制，几十人以内聊天足够用
- 静态版的管理员密码写在前端代码里，**懂技术的人可以绕过**；只适合朋友间玩。
  需要真正的权限管控，请用方案 B（服务端校验）。
- 如果聊天的人多、想长期使用，建议方案 B 或购买正式服务。

## 六、本地先体验

双击打开 `公网版聊天室\index.html` 也能直接用（浏览器允许 file:// 访问 WebSocket）。
推荐用本地服务器预览：在文件夹里执行 `python -m http.server 3001`，
浏览器访问 http://localhost:3001 ，开两个标签页即可模拟两个人。
